Transaction hardening roadmap

The goal is not to add a bigger retry loop. The goal is to make the solver remember every delivery attempt, reconcile against chain reality, and keep moving toward claim even when RPCs, crashes, gas spikes, or duplicate contract calls happen.

What is risky today

Today: one local hash is treated like the whole truth

If the solver broadcasts a transaction and then crashes, times out, loses the RPC response, or later sees an idempotent contract revert, local state can stop matching what actually happened on-chain.

Incremental PR path

PR01

Today

Order fields hold one tx hash per stage. If that field is missing or stale, recovery has little delivery history to use.

Fix

Add TransactionAttempt model, storage, recorder trait, minimal indexes, and tests. No delivery behavior changes yet.

After

The codebase has a durable place to store delivery evidence without changing the business state machine.

Baseenables all later fixes
PR02

Today

A submitted tx can become ambiguous if the RPC times out, returns a nonce error, or the monitor loses context.

Fix

Record planned, broadcast, rejected, indeterminate, confirmed, and reverted attempts at existing Alloy send and monitor points.

After

Every real network send leaves an audit trail. Ambiguous delivery is visible instead of being compressed into order failure.

+0.5less blind retry
PR03

Today

If an order hash write is lost but the tx was broadcast, startup recovery may not know which transaction to inspect.

Fix

Wire handlers to the recorder and let recovery restore missing stage hashes from the best durable attempt.

After

Crash windows shrink. Recovery can repair local state from the ledger and continue the lifecycle.

+0.3hash repair
PR04

Today

The solver can believe fill did not happen even when the contract log history proves it did.

Fix

Add chain-aware reconciliation for fill, post-fill, and claim. Recovery asks the contract/log history what actually completed.

After

If funds are already committed on-chain, the solver advances toward claim instead of waiting on local assumptions.

+0.7fund recovery
PR05

Today

OIF contracts prevent duplicate fill/claim, but duplicate calls can look like terminal failures to the solver.

Fix

Decode already-filled, already-claimed, and already-finalised signals as stage-complete outcomes.

After

Contract idempotency becomes a recovery signal instead of a reason to stop the order.

PR06

Today

A tx can sit pending after a gas spike. Retrying without lineage can create confusion around which attempt won.

Fix

Add same-nonce gas bumping using the attempt ledger as the source of nonce, original tx, and replacement lineage.

After

Stuck pending txs can be replaced deliberately, and recovery can still identify the winning attempt.

+0.5stuck tx escape
PR07

Today

Operators can inspect logs, but there is limited first-class repair tooling and limited chaos coverage for crash windows.

Fix

Add admin repair surfaces, stuck-attempt visibility, metrics, alerts, and crash/RPC/gas-spike tests.

After

The system is not just more resilient; it is observable and repairable during production incidents.

Manager summary

Why this matters

Solver capital is exposed when local state loses track of on-chain progress. The contract prevents duplicate execution, but it cannot make the off-chain solver continue to claim.

Why start with the ledger

Gas bumping, chain reconciliation, and operator repair all need the same source of truth: durable transaction attempts. Building it first avoids a fragile retry-only design.

What success looks like

An order can survive RPC ambiguity, process restart, gas spike, and duplicate contract calls, then still converge to the correct final state and claim path.
